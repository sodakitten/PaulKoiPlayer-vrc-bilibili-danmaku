- 包中不包含其他播放器适配器、后端或测试源码；本轮对其他适配器的改动已撤回，原仓库历史内容保留原样。

## 安装

1. 先备份 Unity 工程。本版以 main 的 YamaPlayer 普通黑白源码为基线；自定义皮肤或黑金版本不能直接覆盖整份 Editor，需单独合并，不把它们视为本轮已验证版本。
2. 将 ZIP 中 `YamaBiliDanmakuV3/` 的内容覆盖到原安装目录（通常为 `Assets/YamaBiliDanmakuV3/`），保留已有 `.meta`、GUID、序列化组件和 UdonSharp Program Asset。不要并排导入两份同名类，不要删除重建播放器、列表或弹幕组件。包根目录的 README 和验证摘要无需导入 Unity。
3. 全量重新编译 UdonSharp。确认 Console 无错误后 Build & Test，最后才上传世界。
4. 主播放器新增 `_pagesPlaylist` 引用。已有列表到弹幕模块的 `_danmakuModule` 引用应保持有效；构建处理器会反向连接弹幕模块到该列表，不要求重新生成 UI。
5. 仅覆盖源码不会更新已经上传的世界；另外一台电脑的 ProTV 影院工程不包含在本包中。

制作环境没有可用 Unity 编辑器或完整 SDK 工程；维护者随后反馈已测试并要求发布。源码/方法检查本身不等于 Unity/UdonSharp 编译或全场景客户端验收，其他工程导入后仍需自行编译并在测试世界确认。

## 协议选择

新安装并通过编辑器创建的插件默认使用 `__pkdm=2`：输入前缀、清单前缀和构建期 VCRID 目录一起选择 V2，不需要再手动开启。媒体请求仍走原 302 播放路径。

已有世界的序列化配置不会因覆盖脚本而被强行改写。若从旧包升级，请选择场景内包含且仅包含一个播放列表的播放器根对象，执行一次：

```text
Tools > PaulKoiPlayer > Backend > Enable Metadata V2 on Selected Player
```

升级菜单的确认窗口会显示两个新前缀，并保留自己的域名及其他查询参数。新安装的默认值同样是：

```text
https://danmaku.paulkoishi.com/player/?__pkdm=2&url=
https://danmaku.paulkoishi.com/player/?__pkdm=2&vcrid=
```

输入前缀、清单前缀和构建期 VCRID 目录同时更新。重新编译、构建世界后生效。不要在媒体播放地址中强制加入 `__dm=1`，它会使媒体播放器收到文本而不是 302。

回退菜单：`Tools > PaulKoiPlayer > Backend > Use Legacy Protocol on Selected Player`。此操作只移除协议标记，不更换域名、编号或删除记录。

V2 后端条件是 `BILIBILI_METADATA_V2_ENABLED=true`、`__pkdm=2`、文本请求、普通 B 站投稿视频同时成立。服务器开关关闭时，即使客户端带版本参数，也仍收到旧完整响应；这属于正常兼容行为。本次没有修改服务器开关，不应仅为安装此包直接重启生产服务。

## 响应处理

| 响应 | 列表 | 弹幕 |
| --- | --- | --- |
| 无新状态字段的旧完整 TSV | 读取原字段 | 解析完整时间轴，仍检查 `#error` |
| `metadata` / `danmaku_complete=0` | 显示完整清单及选中 P | 通过预置目录中该 VCRID 跟进，不当作零条，不消耗错误重试 |
| `complete` / `danmaku_complete=1` | 保留正常列表 | 解析完整时间轴，`count=0` 是有效空结果 |
| `error` / `danmaku_complete=0` | 有可用清单则保留 | 不渲染残缺数据；按是否可重试及剩余冷却处理 |
| `partial`、`pending` 或不完整状态 | 不据此清空有效列表 | 不伪装成完整电影 |

自动重试最多三次，等待不短于本地退避与正文 `retry_after_seconds` 的较大值；无冷却提示的临时失败采用保守 180 秒回退。永久失败不无限重试。切换视频、清空、停止或失去相关请求所有权后，旧请求不能恢复旧列表/弹幕。

运行时只复用预置或用户输入的 VRCUrl，不根据 manifest 字符串创建 URL。构建期目录仍是 1..1000000，0 无效，没有再增加第二套百万项地址数组。

```powershell

```

本轮结果：6 个 C# 文件语法检查、12 项编辑器前缀测试通过，新增默认 V2 配对、实际目录生成和已有配置保留检查；弹幕模块 5865 条、列表模块 130 条实际方法断言通过。断言包含逐帧和逐行重复检查，不等同于同样数量的独立场景。`git diff --check` 通过。测试源码随仓库保留在 `tests/`，交付 ZIP 只附验证摘要。

十万行主模块用例分摊到 1565 个模拟帧，说明没有把整片解析压到单帧，但超大文件完成解析仍需等待；这不是实际 VRChat 帧率或耗时测量。下载保持完整单响应，没有网络分页，也没有恢复隐式条数上限。

新增回归覆盖直接从原生播放器粘贴陌生 VCRID、从另一个 BV 的旧清单切换进来、已知清单内切 P 不重复下载，以及无 `#part` 的自定义条目完整 ID/标题。

## 客户端验收

1. 原入口播放 B 站单 P、多 P、短链/分享文本，自定义别名、网易云单曲和歌单。媒体播放、标题、选中项及歌词不得退化。
2. 上传并播放 7200 条、末条 7199000 ms 的完整时间轴，在 90 分钟和片尾仍有弹幕。100000 条时间轴也应保留全部有效行，同一时间戳多条不能合并丢失。
3. 解析过程中换片、Stop、清空或重新载入，确认旧解析任务和旧网络回调不能恢复画面。暂停、seek、晚加入按现有播放器时钟定位。
4. 隔离后端开启 V2，短链 `https://b23.tv/0PsuP27` 应保留选中 P10；分 P 失败响应仍展示完整列表，之后按冷却重试。
5. 直接播放 VCRID，分别测试成功、HTTP 200 错误正文、180 秒冷却、403/404 和三次重试耗尽。验证没有重复入队或自动退回 P1。
6. 检查换 Owner、连续 A/B/A 切换、清空后的晚到回调，以及错误后的手动重新加载。

官方约束：[字符串下载间隔与大小上限](https://creators.vrchat.com/worlds/udon/string-loading/)、[VRCUrl 构造限制](https://creators.vrchat.com/worlds/udon/external-urls/)。取消条数截断不代表客户端有无限内存；单次响应仍受 SDK 字节限制，极端大文本须另行设计双方支持的分页协议，不能静默只保留前 N 条。
